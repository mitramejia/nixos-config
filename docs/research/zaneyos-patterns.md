# ZaneyOS patterns for a two-host Nix flake

Source snapshot: ZaneyOS commit [`ec8e9d5`](https://gitlab.com/Zaney/zaneyos/-/tree/ec8e9d54b6022837eed7b3f89dc9c37b1257b713), reviewed 2026-07-17. Its [README](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/README.md) defines it as a NixOS configuration, not a macOS/nix-darwin reference; use it for separation-of-concerns patterns rather than as an output topology to copy.

| Pattern observed in ZaneyOS | Evidence | Decision for this repository |
| --- | --- | --- |
| A small output factory creates one `nixosConfiguration` per hardware profile. Each profile imports the selected host plus core and driver module stacks. | [`flake.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/flake.nix), [`profiles/vm/default.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/profiles/vm/default.nix) | **Adopt the factory idea; change the inventory.** Define two concrete host records, `nixos` and `macbook`, and produce `nixosConfigurations.nixos` and `darwinConfigurations.macbook`. Do not copy its mutable top-level `host`/`profile` constants: both hosts must remain independently evaluable. Keep `MitraMacBook` as the macOS hostname, separate from the stable `macbook` configuration key. |
| Per-host files hold hardware, host-only packages, and user-facing choices; a focused core module aggregates system concerns. | [`hosts/default/default.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/hosts/default/default.nix), [`hosts/default/variables.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/hosts/default/variables.nix), [`modules/core/default.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/core/default.nix) | **Adopt, with platform roots.** Keep host-only metadata and hardware in `hosts/nixos` and `hosts/macbook`; place NixOS system modules and nix-darwin system modules in separate platform layers. Pass this metadata as one evaluated host record instead of having individual modules re-import a host file by relative path. This preserves current behavior before later consolidation. |
| The NixOS user module owns Home Manager integration and passes explicit context through `extraSpecialArgs`; the Home Manager root composes focused modules. | [`modules/core/user.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/core/user.nix), [`modules/home/default.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/home/default.nix) | **Adopt the explicit boundary.** Pass a host record (`username`, home directory, hostname, platform) and needed inputs to each Home Manager integration point. Share only genuinely portable developer modules, using the more current NixOS developer setup as the baseline; import explicit `home/nixos` and `home/darwin` layers for divergent UI and OS integration. |
| The Home Manager root conditionally adds modules based on a broad host variables file. | [`modules/home/default.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/home/default.nix) | **Avoid for cross-platform sharing.** Do not make one large `common` module whose imports are mostly `if isDarwin` switches. A small portable dev-tool layer plus explicit platform imports is clearer and matches the agreed migration boundary. |
| Inputs live at the flake root; Home Manager follows the root `nixpkgs`; the repository commits a root `flake.lock`. The source currently tracks `nixos-unstable` and Home Manager `master`. | [`flake.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/flake.nix), [`flake.lock`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/flake.lock) | **Adopt one root input graph, `follows` relationships, and one committed lockfile. Avoid copying the rolling-channel policy.** Preserve this repo's existing 26.05 release pins unless an input needs an explicit, documented exception. |
| `nh` is enabled with a fixed `~/zaneyos` path; shell aliases wrap profile names; `zcli` reads and rewrites `flake.nix` with `grep`/`sed`. Its guide also separates `nix flake check` from activation. | [`modules/core/nh.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/core/nh.nix), [`modules/home/zsh/default.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/home/zsh/default.nix), [`modules/home/scripts/zcli.nix`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/modules/home/scripts/zcli.nix), [`cheatsheets/project-guide.md`](https://gitlab.com/Zaney/zaneyos/-/blob/ec8e9d54b6022837eed7b3f89dc9c37b1257b713/cheatsheets/project-guide.md) | **Adopt the explicit check-versus-switch distinction; avoid path-coupled aliases and config-rewriting wrappers.** Document the agreed direct commands—`nh os switch . -H nixos` and `nh darwin switch . -H macbook`—and provide separate non-activating per-host checks. ZaneyOS is NixOS-only, so its source is not evidence that the darwin command works; validate that command against the installed `nh` version during implementation. |

## Proposed structure

```text
flake.nix                 # inputs, host inventory, output constructors
flake.lock                # one lockfile for both machines
hosts/
  nixos/                  # NixOS hardware and host metadata
  macbook/                # macOS hostname, account, Homebrew-only metadata
modules/
  nixos/                  # NixOS-only system modules
  darwin/                 # nix-darwin-only system modules
  home/
    common/               # portable developer tooling, NixOS baseline
    nixos/                # Linux desktop integration
    darwin/               # macOS integration and Homebrew exceptions
```

This is deliberately two real hosts, not a generic profile framework. It retains each account name (`mitra` and `mitramejia`), keeps Determinate Nix responsible for the macOS Nix installation, confines Homebrew to casks/Apple-only/Nix-unavailable software, and defers secret management. Those are migration decisions for this repository, not ZaneyOS claims.
