# Ryan4yin patterns for a two-host Nix flake

Source snapshot: [`b1e2bb7`](https://github.com/ryan4yin/nix-config/tree/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e), reviewed 2026-07-17. The repository explicitly builds both NixOS and macOS, but it manages more than 20 machines and its own [outputs documentation](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/README.md) says that its fine-grained structure is unnecessary for a small number of machines. Treat it as a source of seams, not a template to reproduce.

| Pattern in the source | Evidence | Decision for this repository |
| --- | --- | --- |
| Host-specific directories are distinct from the output entries that construct each machine. The documented inventory includes separate NixOS and macOS hosts. | [`hosts/README.md`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/hosts/README.md), [`outputs/aarch64-darwin/src/fern.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/aarch64-darwin/src/fern.nix) | **Adopt the separation, not the scale.** Keep `hosts/nixos` and `hosts/macbook` for machine-only facts, with explicit NixOS and Darwin construction paths. Do not introduce its architecture-indexed output tree, Haumea loader, or profile framework for just two real machines. |
| The root output composes NixOS and Darwin independently, groups hosts by system architecture, and exposes `nixosConfigurations` and `darwinConfigurations` separately. | [`outputs/default.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/default.nix), [`outputs/x86_64-linux/default.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/x86_64-linux/default.nix), [`outputs/aarch64-darwin/default.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/aarch64-darwin/default.nix) | **Adopt independently evaluable outputs.** Define only `nixosConfigurations.nixos` (`x86_64-linux`) and `darwinConfigurations.macbook` (`aarch64-darwin`). Preserve `MitraMacBook` as the macOS hostname in the `macbook` host record instead of making it the output key. |
| Inputs are declared once at the flake root; nix-darwin follows its Darwin package source and Home Manager follows the root NixOS package source. A committed root lockfile records the result. | [`flake.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/flake.nix), [`flake.lock`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/flake.lock) | **Adopt one root input graph, deliberate `follows`, and one lockfile. Avoid its many parallel package channels and patched sources.** Preserve the current repo's package policy during the behavior-preserving migration; add a second package set only for a documented need. |
| Both system constructors integrate Home Manager with the system package set and pass context through `extraSpecialArgs`; platform Home Manager roots import shared base modules plus Darwin/Linux-specific layers, with host-level files for exceptions. | [`lib/nixosSystem.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/lib/nixosSystem.nix), [`lib/macosSystem.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/lib/macosSystem.nix), [`home/darwin/default.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/home/darwin/default.nix), [`home/hosts/darwin/darwin-fern.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/home/hosts/darwin/darwin-fern.nix) | **Adopt the three layers:** portable `modules/home/common` for the NixOS-derived developer baseline, explicit `modules/home/nixos` and `modules/home/darwin` layers, then host exceptions. **Adapt its global user variable:** pass the selected host record so `mitra` and `mitramejia` retain their existing account names and home directories. |
| The Darwin module explicitly disables nix-darwin's Nix management because Determinate Nix owns the daemon and installation. | [`modules/darwin/nix-core.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/modules/darwin/nix-core.nix) | **Adopt exactly.** Keep `nix.enable = false` in the Darwin system layer and leave Determinate Nix in charge. Do not copy the unrelated secret-token include from that module while secrets remain deferred. |
| Darwin packages are split between Nix system packages and a managed Homebrew declaration, but its Homebrew list includes command-line formulae as well as casks and uses activation cleanup. | [`modules/darwin/apps.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/modules/darwin/apps.nix) | **Adopt declarative ownership but not this allocation.** Make portable developer tooling from the current NixOS setup the shared Nix baseline. Restrict Homebrew to casks, Apple-specific apps, and tools unavailable or unsuitable in Nix; do not import a broad formula list or destructive Homebrew cleanup policy during migration. |
| Its `Justfile` derives deployment configuration names from the current hostname and wraps native rebuild commands; its README requires manual Nix and Homebrew preparation for a first Darwin deployment. | [`Justfile`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/Justfile), [`README.md`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/README.md#how-to-deploy-this-flake) | **Avoid hostname-coupled wrappers.** The agreed stable keys are `nixos` and `macbook`, independent of the macOS hostname. Document `nh os switch . -H nixos` and `nh darwin switch . -H macbook`, then validate each on its own platform rather than copying the wrapper design. |
| It provides per-system `checks`, formatter and development shells; its documentation distinguishes fast evaluation tests from slower NixOS VM tests. | [`outputs/default.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/default.nix), [`outputs/README.md`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/outputs/README.md#tests) | **Adopt the check-before-switch principle.** Start with formatting, `nix flake check`, and explicit non-activating evaluation/build commands for these two hosts. Defer a custom check framework and VM/integration tests until the unified configuration is stable. |
| Secrets are in a separate private flake input, encrypted with agenix to per-host OpenSSH host keys, and exposed through separate NixOS and Darwin modules. | [`secrets/README.md`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/secrets/README.md), [`secrets/nixos.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/secrets/nixos.nix), [`secrets/darwin.nix`](https://github.com/ryan4yin/nix-config/blob/b1e2bb7e0991de5e170001a2b7bc450d5bbf316e/secrets/darwin.nix) | **Defer.** This is a coherent later model, but adding a private input, host-key encryption, and activation-time secret plumbing would change the migration scope. Migrate no private keys or credentials now; retain only declarative SSH client configuration. |

## Minimal shape justified by these lessons

```text
flake.nix                 # root inputs, host records, two constructors
flake.lock                # one lockfile
hosts/nixos/              # NixOS hardware and host metadata
hosts/macbook/            # MitraMacBook hostname, macOS host metadata
modules/nixos/            # NixOS-only system configuration
modules/darwin/           # nix-darwin configuration; Determinate owns Nix
modules/home/common/      # portable NixOS-first developer tooling
modules/home/nixos/       # Linux desktop and OS integration
modules/home/darwin/      # macOS integration and narrow Homebrew exceptions
```

This preserves the confirmed migration constraints: one canonical repository, behavior preservation before cleanup, exactly two concrete hosts, per-host identities, Determinate Nix on macOS, Nix-managed portable tooling, deferred secrets, and stable configuration keys distinct from hostnames.
